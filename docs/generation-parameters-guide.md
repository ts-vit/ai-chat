# Параметры генерации LLM — Полное руководство

Это руководство описывает все параметры генерации, доступные в ai-chat. Каждый параметр влияет на то, **как** модель выбирает следующее слово (токен) при генерации ответа.

---

## Как модель генерирует текст

Прежде чем разбирать параметры, важно понять базовый принцип. Когда LLM генерирует текст, она на каждом шаге:

1. Вычисляет **вероятности** для каждого токена в словаре (десятки тысяч вариантов)
2. **Фильтрует** кандидатов (Top-K, Top-P)
3. **Корректирует** распределение вероятностей (Temperature)
4. **Штрафует** повторения (Frequency Penalty, Presence Penalty)
5. **Выбирает** один токен из оставшихся кандидатов

Все параметры ниже управляют шагами 2–4 этого процесса.

---

## Temperature (Температура)

### Что делает

Temperature управляет **«уверенностью»** модели при выборе следующего токена. Она изменяет форму распределения вероятностей: делает его более острым (модель уверена) или более плоским (модель «сомневается»).

### Диапазон

`0.0` — `2.0` (в ai-chat по умолчанию `0.7`)

### Как работает

Представь, что модель выбирает следующее слово после фразы «Столица Франции — ...»:

| Токен | Исходная вероятность | При t=0.2 | При t=1.0 | При t=1.5 |
|-------|---------------------|-----------|-----------|-----------|
| Париж | 85% | 99% | 85% | 65% |
| Лион | 8% | 0.8% | 8% | 15% |
| Марсель | 4% | 0.1% | 4% | 12% |
| банан | 0.001% | ≈0% | 0.001% | 0.5% |

- **Низкая температура (0.1–0.3)** — модель почти всегда выбирает самый вероятный токен. Ответы предсказуемые и «скучные», но точные.
- **Средняя температура (0.5–0.8)** — баланс между точностью и разнообразием. Хороший выбор для большинства задач.
- **Высокая температура (1.0–1.5)** — модель чаще выбирает менее вероятные токены. Ответы более креативные, но менее предсказуемые.
- **Очень высокая (>1.5)** — ответы могут стать бессвязными, модель «бредит».

### Примеры использования

| Задача | Рекомендуемая температура |
|--------|--------------------------|
| Код, SQL, математика | 0.0–0.3 |
| Фактические вопросы, FAQ | 0.2–0.5 |
| Обычный чат, помощник | 0.5–0.7 |
| Креативное письмо, стихи | 0.7–1.0 |
| Брейнсторм, генерация идей | 0.9–1.2 |

### Важно

Temperature **не убирает** варианты из списка кандидатов — она только перераспределяет вероятности между ними. Даже при очень низкой температуре «банан» технически остаётся кандидатом (пусть и с вероятностью ≈0%). Чтобы убрать неподходящих кандидатов, нужны Top-K и Top-P.

---

## Top-P (Nucleus Sampling)

### Что делает

Top-P ограничивает список кандидатов **динамически**, оставляя только те токены, чья суммарная вероятность достигает порога P.

### Диапазон

`0.0` — `1.0` (в ai-chat по умолчанию `0.9` при включении)

### Как работает

Допустим, модель рассчитала вероятности для следующего слова:

```
Париж:   50%  → кумулятивно: 50%   ✓ (< 0.9)
Лион:    20%  → кумулятивно: 70%   ✓ (< 0.9)
Марсель: 15%  → кумулятивно: 85%   ✓ (< 0.9)
Тулуза:   8%  → кумулятивно: 93%   ✓ (≥ 0.9, но это первый, перешагнувший порог)
Нант:     4%  → отсечён
банан:    1%  → отсечён
...остальные → отсечены
```

При Top-P = 0.9 модель выберет из {Париж, Лион, Марсель, Тулуза} — минимального набора токенов, покрывающего 90% вероятностной массы.

### Ключевое свойство — адаптивность

Top-P автоматически подстраивается под контекст:

- **«Столица Франции — ...»** — один токен «Париж» уже покрывает 95% вероятности → Top-P=0.9 оставит практически только его.
- **«Мой любимый цвет — ...»** — вероятности распределены равномернее → Top-P=0.9 оставит 10–20 цветов.

Это главное преимущество Top-P перед Top-K: он адаптируется к уверенности модели.

### Примеры

| Top-P | Эффект |
|-------|--------|
| 0.1 | Очень узкий выбор, только самые вероятные токены. Почти детерминированно |
| 0.5 | Умеренно ограниченный выбор |
| 0.9 | Широкий выбор, но без совсем маловероятных вариантов. Рекомендуется как дефолт |
| 0.95 | Ещё шире — для креативных задач |
| 1.0 | Нет фильтрации (все токены — кандидаты) |

### Рекомендация

Общий совет: настраивайте **либо Temperature, либо Top-P**, но не оба одновременно. Если хотите менять оба — делайте это аккуратно и тестируйте результат.

## Top-K

### Что делает

Top-K ограничивает список кандидатов **фиксированным числом** — модель рассматривает только K самых вероятных токенов.

### Диапазон

`1` — `100+` (в ai-chat по умолчанию `40` при включении)

### Как работает

При Top-K = 3 модель берёт 3 самых вероятных токена, отбрасывает все остальные, пересчитывает вероятности среди оставшихся и выбирает из них:

```
Париж:   50%  → оставлен  → новая вероятность: 59%
Лион:    20%  → оставлен  → новая вероятность: 23%
Марсель: 15%  → оставлен  → новая вероятность: 18%
Тулуза:   8%  → отсечён
Нант:     4%  → отсечён
...
```

### Проблема Top-K — негибкость

Top-K всегда оставляет ровно K кандидатов, не учитывая контекст:

- **«Столица Франции — ...»** — при K=50 модель рассматривает 50 токенов, хотя реальный кандидат только один. Это добавляет ненужный шум.
- **«Красивый ...»** — при K=3 модель рассматривает только 3 варианта, хотя подходящих прилагательных/существительных может быть сотни. Это убивает разнообразие.

Именно поэтому Top-P считается более предпочтительным методом фильтрации. OpenAI даже не предоставляет параметр Top-K в своём API.

### Примеры

| Top-K | Эффект |
|-------|--------|
| 1 | Greedy decoding — всегда выбирается самый вероятный токен |
| 10 | Узкий выбор, подходит для точных задач |
| 40 | Умеренный выбор, хороший дефолт |
| 50–100 | Широкий выбор для креативных задач |

### Рекомендация

Используйте **Top-P вместо Top-K** для большинства задач. Top-K полезен если вы работаете с локальными моделями через Ollama и хотите точный контроль над количеством кандидатов.

## Frequency Penalty (Штраф за частоту)

### Что делает

Снижает вероятность токена **пропорционально** тому, сколько раз он уже появился в тексте. Чем чаще слово использовалось — тем сильнее штраф.

### Диапазон

`-2.0` — `2.0` (в ai-chat по умолчанию `0` при включении)

### Как работает

Формула: `новый_скор = исходный_скор - (frequency_penalty × количество_появлений)`

Допустим, слово «кот» уже появилось 5 раз, а penalty = 0.5:

```
Штраф = 0.5 × 5 = 2.5
Скор «кот» снижается на 2.5
```

Если то же слово появилось 1 раз:
```
Штраф = 0.5 × 1 = 0.5
Скор снижается всего на 0.5
```

Чем чаще слово появлялось — тем сильнее штраф. Это **пропорциональный** механизм.

### Примеры

**Без Frequency Penalty (0.0):**
> «Лучший спорт — это футбол. Футбол — это весело. Футбол — это захватывающе. Футбол — это лучшее.»

**С Frequency Penalty (0.5):**
> «Лучший спорт — это футбол. Он захватывает и дарит эмоции. Матчи приносят радость и объединяют людей.»

**С Frequency Penalty (1.5):**
> «Лучший спорт — это футбол. Баскетбол тоже отличный выбор. Плавание укрепляет тело. Шахматы развивают мышление.»

### Когда использовать

- **0.0** — по умолчанию, без штрафа
- **0.1–0.5** — лёгкое снижение повторов, подходит для большинства задач
- **0.5–1.0** — заметное разнообразие, хорошо для статей и эссе
- **1.5–2.0** — агрессивное подавление повторов, может снизить качество текста
- **Отрицательные значения** — наоборот, поощряют повторение (редко нужно)

---

## Presence Penalty (Штраф за присутствие)

### Что делает

Снижает вероятность токена **одинаково**, если он хотя бы раз появился в тексте. Не важно, появился он 1 раз или 100 — штраф одинаковый.

### Диапазон

`-2.0` — `2.0` (в ai-chat по умолчанию `0` при включении)

### Как работает

Формула: `новый_скор = исходный_скор - presence_penalty` (если токен появлялся хотя бы раз)

Если слово «кот» появилось 1 раз, penalty = 0.5:
```
Штраф = 0.5
```

Если слово «кот» появилось 10 раз, penalty = 0.5:
```
Штраф = 0.5 (тот же!)
```

Это **фиксированный** штраф — достаточно одного появления.

### Примеры

**Без Presence Penalty (0.0):**
> «Собака лает. Собака играет. Собака бегает.»

**С Presence Penalty (0.5):**
> «Собака лает. Кошка играет. Кролик бегает.»

### Разница с Frequency Penalty

| | Frequency Penalty | Presence Penalty |
|---|---|---|
| **Как штрафует** | Пропорционально количеству появлений | Фиксированно, за сам факт появления |
| **«кот» появился 1 раз** | Маленький штраф | Полный штраф |
| **«кот» появился 10 раз** | Большой штраф (в 10 раз больше) | Тот же штраф |
| **Эффект** | «Не повторяй слишком часто» | «Используй новые слова» |
| **Аналогия** | Мягкое напоминание: «ты уже часто это говоришь» | Жёсткое правило: «раз сказал — ищи другое» |

### Когда что использовать

- **Frequency Penalty** — когда допустимо повторение, но не хочется переборов. Слово «алгоритм» в статье по программированию может повторяться, но не в каждом предложении.
- **Presence Penalty** — когда хочется максимального разнообразия тем и лексики. Например, для генерации списка идей, где каждый пункт должен быть о чём-то новом.
- **Оба вместе** — можно комбинировать, но осторожно. Высокие значения обоих штрафов могут сделать текст неестественным.

## Max Tokens (Максимальная длина)

### Что делает

Ограничивает **максимальное количество токенов** в ответе модели. Один токен — это примерно 3/4 слова на английском или 1/2 слова на русском.

### Как работает

Модель прекращает генерацию когда:
1. Сгенерировала специальный токен конца ответа (естественное завершение), **или**
2. Достигла лимита Max Tokens (принудительная остановка)

### Примеры

| Max Tokens | Примерный объём |
|------------|----------------|
| 256 | Короткий абзац |
| 1024 | Страница текста |
| 4096 | Несколько страниц |
| 8192+ | Длинные тексты, код |

### Важно

- Не путайте max tokens (ответ) с контекстным окном модели (промпт + ответ)
- Если модель «обрезается» на середине предложения — увеличьте max tokens
- Больше токенов = дольше генерация и выше стоимость (для платных API)

## Сводная таблица рекомендаций

### По типу задачи

| Задача | Temperature | Top-P | Top-K | Freq Penalty | Pres Penalty |
|--------|-------------|-------|-------|--------------|--------------|
| Код, SQL | 0.0–0.2 | 0.1–0.3 | — | 0 | 0 |
| Фактические ответы | 0.1–0.3 | 0.3–0.5 | — | 0 | 0 |
| Саммари, рерайт | 0.3–0.5 | 0.7–0.9 | — | 0.3–0.5 | 0 |
| Чат, помощник | 0.5–0.7 | 0.9 | — | 0 | 0 |
| Статьи, эссе | 0.6–0.8 | 0.9 | — | 0.3–0.7 | 0.1–0.3 |
| Креативное письмо | 0.8–1.0 | 0.9–0.95 | — | 0.5–1.0 | 0.3–0.5 |
| Брейнсторм, идеи | 0.9–1.2 | 0.95 | — | 0.5 | 0.5–1.0 |

### Общие правила

1. **Начинайте с дефолтов** — Temperature 0.7, остальное выключено
2. **Меняйте один параметр за раз** — так проще понять эффект
3. **Temperature или Top-P, не оба** — меняйте что-то одно
4. **Top-P предпочтительнее Top-K** — он адаптивный
5. **Штрафы нужны редко** — используйте при заметных повторах
6. **Тестируйте** — одна и та же настройка работает по-разному с разными моделями

## Применение в ai-chat

В приложении ai-chat все параметры опциональные:

- **Temperature и Max Tokens** — всегда активны, имеют дефолтные значения
- **Top-P, Top-K, Frequency Penalty, Presence Penalty** — по умолчанию выключены
- При **выключенном** параметре он не отправляется в API — модель использует свои дефолты
- При **включении** выставляется рекомендуемое начальное значение

Параметры применяются глобально ко всем чатам (хранятся в настройках приложения, не per-чат).

### Совместимость с провайдерами

| Параметр | OpenRouter | Ollama | OpenAI-совместимые |
|----------|-----------|--------|-------------------|
| Temperature | ✅ | ✅ | ✅ |
| Max Tokens | ✅ | ✅ | ✅ |
| Top-P | ✅ | ✅ | ✅ |
| Top-K | ⚠️ зависит от модели | ✅ | ⚠️ не все поддерживают |
| Frequency Penalty | ✅ | ✅ | ✅ |
| Presence Penalty | ✅ | ✅ | ✅ |

> ⚠️ Top-K не входит в стандартный OpenAI API. Он поддерживается Ollama, Google (Gemini), Anthropic и некоторыми другими провайдерами, но не всеми. Если провайдер не поддерживает параметр, он обычно его молча игнорирует.
